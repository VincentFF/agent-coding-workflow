# ECC Sources, Usage, and Maintenance

This collection adapts seven skills and five Agent review/recovery practices from Everything Claude Code (ECC) into `.agents/skills/` for use across coding agents (pi, Codex, ZCode). These skills provide concise, actionable methods. They are not direct verbatim copies of the upstream repository, and they do not install ECC agent configurations, hooks, or runtime plugins.

Pinned upstream: [affaan-m/ECC](https://github.com/affaan-m/ECC/tree/b38be6a7f6350964d59328b52f0624e1d1d552d1), revision `b38be6a7f6350964d59328b52f0624e1d1d552d1`. Retained upstream [MIT License](ECC-UPSTREAM-LICENSE) (Copyright (c) 2026 Affaan Mustafa). PostgreSQL patterns retain upstream Supabase team attribution; prompt caching retains cyberspace-cs attribution.

## Usage and Loading Model

- Use [task methods](task-methods.md) as the central routing index.
- Core skills ([tdd](../../tdd/SKILL.md), [code-review](../../code-review/SKILL.md), [design-writing](../../design-writing/SKILL.md)) link to these methods at relevant boundaries.
- Handoffs in [execution](execution.md) provide absolute paths only for applicable skills and references.
- Specialist references are read-only perspectives for existing `implementer`, `code-reviewer`, and `oracle` roles. No new agent roles or extra routine stages are created.

## Platform Discovery and Verification

Skills reside in `.agents/skills/`.
- **pi**: Natively discovers skills under `.agents/skills/`. Run `/reload` after installing or updating. Explicitly invoke with `/skill:<name>` when needed.
- **ZCode**: Discovers project skills under `.agents/skills/`. Verify with `zcode skills list --cwd <project> --json`. Hand off absolute paths during delegation.
- **Codex**: Discovers project skills under `.agents/skills/`.
- Markdown files provide behavior guidelines for agents. They do not enforce runtime sandboxing, process confinement, or automatic tool interception.

## Maintenance and Upgrades

When evaluating updates from upstream ECC:
1. Pin a specific commit SHA; do not track a moving branch tip.
2. Compare only the specific files listed in the table above.
3. Read the upstream changes completely and adapt them into concise, generalized instructions.
4. Verify that project contracts, licensing notices, and attribution remain intact.
5. Never overwrite project-specific deployment contracts, validation commands, or architectural decisions with generic upstream rules.
