# 示例：一次小型行为变更

这个示例展示工作流产出的最小形态，不包含真实业务代码。假设项目要为一次 HTTP 接收接口增加"正文超限返回 413"的行为。

## 安装后的项目结构

```text
project/
├── AGENTS.md                       # 含 coding-playbook 受控区块
└── .agents/
    ├── project-workflow.md         # 项目事实：文档位置、验证命令、授权
    ├── coding-playbook.lock.json   # 安装记录
    └── skills/                     # 分发的通用技能
```

## 交付目录

```text
docs/changes/2026-10-29-request-body-limit/
├── change.md
└── spec.md
```

### `change.md`

```markdown
# 请求正文超限拒绝

状态：approved
批准依据：2026-10-29 负责人确认本材料集合。
依赖：无

## 目标与边界

接收接口目前对超大正文没有明确结果。本次让超限请求稳定返回 413，且不保存任何截断内容。

不包含：调整上限数值、增加压缩支持、修改已保存数据的处理。

## 变更摘要

主要变化：正文超限从"取决于连接行为"变为稳定返回 413。
必须保留的重要承诺：认证失败仍不读取正文；合法请求的保存与确认语义不变。

本次批准材料：

- 本文件
- [spec.md](spec.md)：接收接口的目标行为
- `docs/specs/http.md`「请求接收」：当前行为基线

## 实施计划

- [ ] 在正文读取处显式限制大小，超限映射为 413；完成条件是超限请求返回 413 且不写入存储。
- [ ] 补充超限与短读的区分；完成条件是两者返回不同结果。
- [ ] 合并目标行为到 `docs/specs/http.md`；完成条件是当前 Spec 与实现一致。

## 验收

- 发送超过上限的正文：返回 413，存储中无新增记录。
- 发送截断正文（连接中断）：返回 400，存储中无新增记录。
- 发送合法请求：返回既有成功结果，行为与合并前一致。
- 证明边界：以上需在真实 HTTP 与真实存储上验证；单进程函数测试不足以证明"未写入"。

## 文档合并

`docs/specs/http.md`「请求接收」：用目标规则替换现有描述，保留认证与成功确认规则。

## 交付结论

（交付完成后填写）
```

### `spec.md`

```markdown
# 请求接收 行为契约（本次目标）

本次交付后应达到的行为。当前基线见 `docs/specs/http.md`「请求接收」。

## 输入与前置条件

先认证，再读取正文。认证失败返回 401，不读取正文。

## 结果与状态

正文超过上限返回 413，不保存截断内容。正文完整且校验通过时按既有规则保存并确认。

## 失败与限制

正文不完整返回 400。413 和 400 都必须能区分，不能合并为同一结果。

## 关键场景

- 超限：413，无新增记录。
- 短读：400，无新增记录。
- 合法：既有成功结果。
```

## 说明

- `spec.md` 只写受影响的能力，不复制整个应用 Spec。
- 变更摘要只讲差异和必须保留的承诺，不重述完整系统。
- 验收写明"未写入"需要真实存储证据，而不只是返回码。
- 交付后，`spec.md` 的已交付内容合并进 `docs/specs/http.md`；归档的 `spec.md` 保留为历史依据。
